## 问题出现了...

随着使用 AI 编程的频率增加，问题也随之而来。

### 经典场景

#### 场景 1：修改一个函数，结果改了十个文件

```
我：请帮我修改 login 函数的密码验证逻辑
AI：好的，我修改了以下内容：
- ✅ 修改了 login 函数
- ✅ 修改了 user 模型
- ✅ 修改了数据库迁移文件
- ✅ 修改了前端登录页面
- ✅ 修改了 API 文档
- ✅ ...（还有 20 个文件）
```

**我**：？？？我只是想改个密码验证啊！

#### 场景 2：理解错了需求

```
我：把这个按钮改成蓝色
AI：好的，我把整个页面的主题色都改成了蓝色
```

**我**：...

#### 场景 3：过度优化

```
我：帮我修复这个 typos
AI：好的，我除了修复 typos，还：
- 重构了整个模块
- 添加了类型定义
- 优化了性能
- 写了单元测试
```

**我**：我只是想改个拼写错误啊！

### 问题根源分析

| 问题 | 根源 | 解决方案 |
|------|------|----------|
| AI 乱改代码 | 缺少 Rules 约束 | 使用 Rules 明确约束 AI 的行为 |
| 理解错需求 | 需求描述模糊 | 提供清晰、具体的指令 |
| 过度优化 | AI 过度理解 | 明确说明"只修改 X，不要改动其他" |
| 上下文缺失 | 信息不完整 | 提供完整的上下文信息 |

## AI 编程常见问题诊断清单

### 问题 1：AI 乱改代码

**可能原因**：
- 没有明确的 Rules 约束
- 需求描述模糊
- AI 过度理解

**解决方案**：
- 使用 Rules 明确约束
- 提供清晰具体的指令
- 明确说明"只修改 X"

### 问题 2：AI 理解错需求

**可能原因**：
- 上下文缺失
- 指令过于简略

**解决方案**：
- 提供完整的上下文
- 使用模板化指令

### 问题 3：AI 输出质量不稳定

**可能原因**：
- 指令不一致
- 缺少示例

**解决方案**：
- 保持指令格式一致
- 提供示例参考
