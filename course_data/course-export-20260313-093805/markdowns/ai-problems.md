## 问题出现了...

随着使用 AI 编程的频率增加，问题也随之而来。

### 经典场景

#### 场景 1：修改一个函数，结果改了十个文件

```
我：请帮我修改 login 函数的密码验证逻辑
AI：好的，我修改了以下内容：
- ✅ 修改了 login 函数
- ✅ 修改了 user 模型
- ✅ 修改了数据库迁移文件
- ✅ 修改了前端登录页面
- ✅ 修改了 API 文档
- ✅ ...（还有 20 个文件）
```

**我**：？？？我只是想改个密码验证啊！

#### 场景 2：理解错了需求

```
我：把这个按钮改成蓝色
AI：好的，我把整个页面的主题色都改成了蓝色
```

**我**：...

#### 场景 3：过度优化

```
我：帮我修复这个 typos
AI：好的，我除了修复 typos，还：
- 重构了整个模块
- 添加了类型定义
- 优化了性能
- 写了单元测试
```

**我**：我只是想改个拼写错误啊！

### 问题根源分析

| 问题 | 根源 | 解决方案 |
|------|------|----------|
| AI 乱改代码 | 缺少 Rules 约束 | 使用 Rules 明确约束 AI 的行为 |
| 理解错需求 | 需求描述模糊 | 提供清晰、具体的指令 |
| 过度优化 | AI 过度理解 | 明确说明"只修改 X，不要改动其他" |
| 上下文缺失 | 信息不完整 | 提供完整的上下文信息 |

## 测验：AI 问题识别测验

**及格分数**: 60


### 问题 1

【场景】你和 AI 的对话：

你：请帮我修改 login 函数的密码验证逻辑
AI：好的，我修改了以下内容：
  - ✅ 修改了 login 函数
  - ✅ 修改了 user 模型
  - ✅ 修改了数据库迁移文件
  - ✅ 修改了前端登录页面
  - ✅ 修改了 API 文档

你：？？？我只是想改个密码验证啊！

问题：导致 AI 改了这么多文件的根本原因是什么？
- [ ] AI 过于兴奋，想要展示自己的能力
- [x] 指令没有明确指定修改范围，AI 默认进行完整实现
- [ ] 密码验证本身就需要修改这么多文件
- [ ] AI 模型有 bug，无法理解函数级别修改

**答案**: 1
**解析**: 指令没有明确指定修改范围，AI 默认进行'完整实现'。应该在 Prompt 中明确限制修改范围，如'只修改 login 函数中的密码验证逻辑，不要改动其他文件'。


### 问题 2

【诊断】以下需求描述存在什么问题？

'把这个页面弄得好看一点，用户友好一些'
- [ ] 描述太长，AI 记不住
- [x] '好看'和'用户友好'是主观模糊的描述，无法执行
- [ ] 没有指定使用什么 CSS 框架
- [ ] 应该提供设计稿而不是文字描述

**答案**: 1
**解析**: '好看'和'用户友好'是主观且模糊的描述，AI 无法准确理解。应该具体说明：颜色方案、布局调整、交互反馈等具体要求。


### 问题 3

【决策】当你发现 AI 改了不该改的文件时，应该怎么做？
- [ ] 放弃使用 AI，太不可靠了
- [ ] 继续让 AI 改，改到对为止
- [x] 撤销改动，用更明确的指令重新沟通，指定修改范围
- [ ] 向 AI 抱怨它理解能力太差

**答案**: 2
**解析**: 最佳做法是：1) 撤销改动；2) 用更明确的指令重新沟通，指定修改范围；3) 考虑将此约束加入 Rules。抱怨或放弃都不是建设性的做法。

## AI 编程常见问题诊断清单

### 问题 1：AI 乱改代码

**可能原因**：
- 没有明确的 Rules 约束
- 需求描述模糊
- AI 过度理解

**解决方案**：
- 使用 Rules 明确约束
- 提供清晰具体的指令
- 明确说明"只修改 X"

### 问题 2：AI 理解错需求

**可能原因**：
- 上下文缺失
- 指令过于简略

**解决方案**：
- 提供完整的上下文
- 使用模板化指令

### 问题 3：AI 输出质量不稳定

**可能原因**：
- 指令不一致
- 缺少示例

**解决方案**：
- 保持指令格式一致
- 提供示例参考
