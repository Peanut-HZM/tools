## 柳暗花明！

当我发现 rules 的时候，感觉就像发现了新大陆！

### 什么是 Rules？

Rules 是一组规则文件，用来规范 AI 的行为。它告诉 AI：

- ✅ **应该做什么**
- ❌ **不应该做什么**
- 📋 **如何思考和行动**

### Rules 为什么有效？

AI 模型在生成回应时，会优先考虑最近的、明确的指令。Rules 就是预先设置的明确指令，让 AI 在每次回应前都"记住"这些约束。

**工作原理**：

1. **上下文注入**：Rules 作为系统上下文的一部分被注入到每次对话中
2. **优先级处理**：AI 会优先遵循 Rules 中的指令
3. **行为约束**：Rules 限定了 AI 的输出范围和行为模式

### Rules 编写指南

#### 基本结构

```markdown
# AI 助手行为规范

## 章节标题

1. **具体规则**：规则内容
2. **另一条规则**：规则内容
```

#### 语法规范

- 使用清晰的标题
- 使用编号列表
- 每条规则应该是可执行的
- 避免模糊的词汇（如"可能"、"尽量"）

#### 最佳实践

1. **具体**：不要说"保持代码质量"，要说"遵循 PEP8 规范"
2. **可执行**：规则应该是 AI 能够执行的
3. **有优先级**：重要规则放在前面
4. **覆盖常见场景**：预先考虑常见场景并设置规则

### 我的第一条 Rules

```markdown
# AI 助手行为规范

## 代码修改原则

1. **最小化修改**：只修改我明确要求修改的部分
2. **不要擅自添加**：不要添加我未要求的功能
3. **保持原有风格**：保持代码的原有风格和格式
4. **说明变更**：修改前先告诉我改了哪里

## 代码质量要求

1. 添加必要的注释
2. 遵循项目的代码规范
3. 考虑边界情况
```

### 使用 Rules 后的变化

| 之前 | 后 |
|------|------|
| AI 乱改一堆代码 | 只改我要求的地方 ✅ |
| 需要大量 review | 改动清晰，快速 review ✅ |
| 经常要反复修正 | 第一次就做对 ✅ |
| 感觉 AI 很笨 | 感觉 AI 变聪明了 ✅ |

## 测验：Rules 应用测验

**及格分数**: 60


### 问题 1

【场景】对比两次 AI 编程体验：

使用前：
- 每次都要重复说明'用 TypeScript''用中文回复''要写注释'
- AI 经常忘记之前的约束
- 同样的话要说很多遍

使用后（配置了 Rules）：
- AI 自动遵循预设规范
- 代码风格一致
- 沟通效率大幅提升

问题：Rules 为什么有效？
- [ ] AI 被 Rules 限制了，不敢乱来
- [x] Rules 作为系统上下文，每次对话都会被 AI 优先考虑
- [ ] Rules 改变了 AI 模型的权重
- [ ] 心理作用，实际上没区别

**答案**: 1
**解析**: Rules 作为系统上下文的一部分被注入到每次对话中，AI 会优先遵循这些明确的指令。这比每次重复沟通要高效得多。


### 问题 2

【诊断】以下这条 Rules 存在什么问题？

'修改代码时要小心，不要破坏现有功能，保持代码整洁'
- [ ] 规则太长，AI 记不住
- [x] 规则过于模糊，'小心''整洁'等词汇无法执行
- [ ] 规则数量太少，需要更多
- [ ] 规则没有用编号列表

**答案**: 1
**解析**: '小心''不要破坏''整洁'都是模糊词汇，AI 无法准确执行。好的 Rules 应该是可执行的，如'修改前先运行测试''保持与现有代码风格一致'。


### 问题 3

【决策】当你想要 AI 只修改指定文件而不改动其他文件时，应该使用哪条 Rules？
- [ ] 不要乱改代码
- [ ] 修改代码前要先思考
- [x] 仅修改用户明确指定的文件，不新增或删除任何文件；修改前需先说明改动范围
- [ ] 尽量保持代码整洁

**答案**: 2
**解析**: 选项 3 最具体且可执行：明确了修改范围（仅指定文件）、禁止行为（不新增/删除文件）、额外要求（修改前说明）。其他选项要么太模糊，要么不够全面。
