# 数据库安全组网（WireGuard）与多设备接入指南

> 更新日期：2026-10-24
> 适用范围：所有需要从本地开发机连接服务器数据库（PostgreSQL / MySQL / Redis）的设备

---

## 1. 背景与目标

服务器上的 PostgreSQL(5432)、MySQL(3306)、Redis(6379) 曾直接暴露公网，仅靠密码防御，
存在被无限速暴力破解的风险（Redis 破解后还可能 RCE 提权到服务器）。

**目标：数据库端口对公网完全关闭，同时所有开发设备依然可以随时连接使用。**

方案：WireGuard 组网。服务器与所有开发设备组成一个加密虚拟内网（`10.8.0.0/24`），
数据库通过内网地址 `10.8.0.1` 访问。WireGuard 不响应任何未认证数据包，公网扫描完全不可见，
比「开放端口 + 密码」安全一个量级。

## 2. 组网架构

```
开发设备A(10.8.0.2) ──┐
开发设备B(10.8.0.3) ──┼── WireGuard 加密隧道(UDP 51820) ──→ 服务器 10.8.0.1
开发设备C(10.8.0.4) ──┘                                      ├─ PostgreSQL 10.8.0.1:5432
                                                             ├─ MySQL      10.8.0.1:3306
                                                             └─ Redis      10.8.0.1:6379
```

- 内网网段：`10.8.0.0/24`，服务器固定为 `10.8.0.1`，设备从 `10.8.0.2` 起自动递增分配
- 流量为 Split-tunnel：仅访问 `10.8.0.x` 的流量走隧道，设备正常上网不受任何影响
- 每台设备持有独立密钥对，可单独吊销

## 3. 服务端已部署内容（服务器上）

| 项目 | 路径 / 命令 |
|------|-------------|
| WireGuard 配置 | `/etc/wireguard/wg0.conf`（含服务端私钥与各设备 Peer 段，勿外传） |
| 服务端密钥 | `/etc/wireguard/server.key`（私钥，权限 600）、`server.pub` |
| 启停/状态 | `wg-quick up wg0` / `wg-quick down wg0` / `wg show` |
| **新增设备脚本** | `/root/wg-add-device.sh <设备名>` |
| 各设备配置文件 | `/root/<设备名>-tunnel.conf`（由脚本生成，取回设备导入） |

安全组基线要求：
- **放行**：UDP 51820（WireGuard，对扫描不可见）、TCP 22/80/443/1443/2222
- **关闭公网入方向**：TCP 3306 / 5432 / 6379 / 8848 / 9848（数据库与 Nacos 只走内网/隧道）

## 4. 新设备接入流程（三步）

### 第 1 步：服务器上生成该设备的配置

```bash
ssh <服务器SSH别名>          # 或直接 ssh root@<服务器IP>
/root/wg-add-device.sh my-mac2     # 设备名自取，如 win1 / mac2 / ubuntu-dev
# 输出: 设备 my-mac2 已添加, 内网IP=10.8.0.3, 配置文件: /root/my-mac2-tunnel.conf
```

### 第 2 步：把配置取回新设备

```bash
# 在新设备上执行（或在服务器所在网络用 U 盘/加密渠道传输，勿走聊天工具明文发送）
scp <服务器SSH别名>:/root/my-mac2-tunnel.conf ~/my-mac2-tunnel.conf
```

> 配置文件内含该设备的**私钥**，等同于数据库通行证：不要提交到任何仓库、
> 不要通过微信/QQ/邮件明文传输；设备遗失后立即在服务器吊销（见第 7 节）。

### 第 3 步：在新设备上安装客户端并导入

**macOS（推荐图形版）**
1. App Store 安装 **WireGuard** 应用
2. 文件 → 从文件导入 → 选择 `my-mac2-tunnel.conf`
3. 点「连接」；或者命令行方式：`brew install wireguard-tools` 后
   `sudo wg-quick up ~/my-mac2-tunnel.conf`

**Windows**
1. 官网下载安装 WireGuard（wireguard.com/install）
2. 打开应用 → Import tunnel(s) from file → 选择配置文件 → Activate

**Linux**
```bash
sudo apt install wireguard
sudo wg-quick up ~/my-mac2-tunnel.conf        # 配置需拷到 /etc/wireguard/ 下可用名称调用
```

**验证隧道**：`ping 10.8.0.1`，以及 `wg show`（客户端）或服务器 `wg show`
应能看到 latest handshake 时间。若始终无 handshake，见第 9 节排查。

## 5. 数据库连接方式（隧道建立后）

所有工具统一使用内网地址 `10.8.0.1`（不再使用公网 IP/域名直连数据库）：

| 数据库 | 地址 | 说明 |
|--------|------|------|
| PostgreSQL | `10.8.0.1:5432` | 库：tokenproxy / tools / gitea 等 |
| MySQL | `10.8.0.1:3306` | |
| Redis | `10.8.0.1:6379` | 需密码 |

**图形工具（Navicat / DBeaver / DataGrip）**：主机填 `10.8.0.1`，端口/账号密码照旧。

**命令行示例**：
```bash
psql -h 10.8.0.1 -U postgres -d tokenproxy
mysql -h 10.8.0.1 -u <用户> -p
redis-cli -h 10.8.0.1 -p 6379 -a <密码>
```

**本地代码/应用连接**：把连接串里的数据库主机改为 `10.8.0.1` 即可，
其余（端口、库名、账号）不变。例如：
`postgresql://<用户>:<密码>@10.8.0.1:5432/<库名>`

## 6. 旧连接方式迁移说明（确保功能不受影响）

安全组关闭数据库端口公网后，以下旧用法会**立即失效**，需要一次性切换：

| 旧用法（将失效） | 切换为 |
|------------------|--------|
| GUI 工具直连 `公网IP:5432/3306/6379` | 先连 WireGuard，主机改 `10.8.0.1` |
| 代码/脚本连接串里写 `公网IP:数据库端口` | 主机改 `10.8.0.1`，其余不变 |
| 服务器上服务互连用 `公网IP:端口` | 改为 `127.0.0.1:端口`（同机）或 `172.17.0.1:端口`（Docker 容器内） |

检查点：切换前全局搜索本地项目里的数据库连接配置（`.env`、`application.yml`、
`settings.py` 等），凡指向公网地址的都按上表替换。服务器同机服务已改用
`127.0.0.1` 的不受影响；Docker 容器内经 `172.17.0.1` 访问宿主机数据库的不受影响。

## 7. 设备管理

**新增设备**：重复第 4 节流程（服务器一条命令 + 拷配置 + 导入）。

**吊销设备**（丢失/淘汰/换密钥）：
```bash
# 服务器上编辑 /etc/wireguard/wg0.conf，删除该设备对应的 [Peer] 段（有 # 设备名注释），然后：
wg syncconf wg0 <(wg-quick strip wg0)     # 立即生效，无需重启隧道
```
吊销后该设备的配置文件即作废，即使泄露也无法连接。需要时重新生成新配置。

**查看在线状态**：服务器 `wg show` 可见每个 Peer 的最近握手时间与流量。

## 8. 日常使用注意事项

- 隧道是按需启动的：设备重启后需重新连接（图形版点一下，命令版重跑 `wg-quick up`）。
  需要常驻可将命令加入开机自启/登录项。
- 连接数据库前确认 WireGuard 已连接（`wg show` 有 handshake 或 ping 10.8.0.1 通）。
- 服务器侧 WireGuard 服务已设置开机自启（`systemctl enable wg-quick@wg0`），
  服务器重启后无需手动操作。

## 9. 故障排查

| 现象 | 排查顺序 |
|------|----------|
| `wg show` 始终无 latest handshake | ① 安全组是否放行 UDP 51820 入方向；② 客户端 Endpoint 的 IP/端口是否正确；③ 服务器 `systemctl status wg-quick@wg0` 是否运行 |
| handshake 正常但连不上 10.8.0.1:5432 | ① 服务器 `ss -tlnp \| grep 5432` 确认 PG 在监听；② pg_hba 是否放行 10.8.0.0/24 网段；③ 防火墙（ufw/iptables）是否拦截 wg0 |
| 能连库但认证失败 | 账号/密码问题，与隧道无关；检查所用账号与库权限 |
| 设备上网变慢/异常 | 检查客户端配置 `AllowedIPs` 是否误写为 `0.0.0.0/0`（应为 `10.8.0.0/24`，仅内网走隧道） |

## 10. 安全红线

1. 设备配置文件（`*-tunnel.conf`）**含私钥**：不进 git、不发聊天工具、不共享给他人
2. 每台设备独立密钥，**禁止多台设备复用同一份配置**（否则无法单独吊销）
3. 数据库端口（3306/5432/6379）永远不要重新对公网开放——需要新设备就进 WireGuard
4. 服务器上 `/etc/wireguard/` 与 `/root/*-tunnel.conf` 权限保持 600
