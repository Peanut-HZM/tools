# 小程序工具迁移设计

## 1. 背景

`frontend` Web 端已经提供较多工具入口，而 `tools-mini-program` 目前只迁移了部分移动端页面。用户希望把适合移动端实现的工具尽量完整迁移到小程序，避免小程序工具箱长期缺少 Web 端已有能力。

本设计只覆盖需求、架构和迁移策略，不直接实施代码。后续实施应基于本文拆分计划，按批次迁移和验证。

## 2. 已确认边界

- 迁移边界采用“普通用户工具优先”。
- 微信小程序优先，Taro H5 仅作为基础预览兼容。
- 不把小程序做成移动端运维控制台。
- 不迁移或默认隐藏高风险、本机强依赖、桌面交互强依赖的工具。
- 优先复用现有后端 API，不在第一轮迁移中新增大型后端能力。
- 小程序页面要针对移动端重做交互，而不是机械复制 Web 桌面布局。

“普通用户工具”的判定标准：

- 不需要服务器运维权限。
- 不执行破坏性操作，例如删除数据库、终止进程、批量清空缓存。
- 不依赖桌面文件系统、本机 IDE 数据或终端交互。
- 不暴露基础设施凭据，例如数据库、Redis、SSH 连接信息。
- 可以通过手机输入、选择文件、复制文本、阅读内容、查看只读统计完成核心流程。

## 3. 工具迁移矩阵

本矩阵基于 `frontend/src/App.tsx` 的 Web 工具路由、`backend/app/data/tools_data.py` 的工具数据，以及 `tools-mini-program/src/app.config.ts` 和 `tools-mini-program/src/services/tool.ts` 的小程序页面与路径映射盘点。后续新增 Web 工具如果未出现在本矩阵中，默认不得在小程序展示，必须先补充本设计或后续计划中的迁移判定。

迁移实施前必须以本表为依据核对接口。若接口路径、权限或返回结构与实际代码不一致，先修正文档或实施计划，不直接猜测实现。

| 工具 | 现有接口 | 状态 | 小程序适配要求 |
| --- | --- | --- | --- |
| 图片下载 | `POST /api/image-downloader/extract-images`、`GET /api/image-downloader/download`、`GET /api/image-downloader/history`、`GET /api/image-downloader/quota` | 已有 | 小程序只做单图保存和复制链接；批量下载后置 |
| 视频下载 | `POST /api/tools/extract-videos`、`POST /api/tools/download-video-ytdlp`、`GET /api/tools/download-task/{task_id}`、`GET /api/tools/download-file/{task_id}`、`GET /api/tools/video-formats` | 已有 | 需要任务轮询；大文件优先复制或打开链接 |

## 5. 小程序信息架构

采用“主包保留核心入口，新增工具使用分包”的结构。

### 5.1 主包

主包保留以下内容：

- 首页工具搜索、分类、工具卡片。
- TabBar：工具、消息、文件、我的。
- 账号相关页面：登录、注册、个人中心、修改密码。
- 现有高频工具：JSON、日历、密钥生成、OCR、ASR、HTTP、OpenClaw、CrossShare。

### 5.2 分包

| 分包 | 页面 |
| --- | --- |
| `package-media` | 图片下载、视频下载 |
| `package-docs` | 文档转 Markdown、Markdown 轻量编辑器 |
| `package-learning` | 课程列表、课程详情、章节学习、技术内容列表、技术内容详情 |
| `package-stats` | Token 统计只读面板 |
| `package-ai` | 后置预留；AI 助手确认合规和 API 后再启用 |

### 5.3 首页入口治理

首页工具卡片仍从后端 `/tools?platform=mobile` 获取，但小程序本地必须维护 `TOOL_PATH_MAP`。

工具入口必须同时满足：

1. 后端返回 `status=online` 且 `show_mobile=true`。
2. 小程序 `TOOL_PATH_MAP` 存在有效页面路径。
3. 对应页面已在 `app.config.ts` 的 `pages` 或 `subPackages` 中注册。

不满足条件的工具不展示。这样可以避免后端误配置后产生死入口。

入口注册规范：

- 工具 ID 必须沿用后端 `tools.id`，不得为小程序另起别名。
- 分包路径统一使用 `/package-*/pages/<tool-id>/index` 或清晰等价路径。
- `TOOL_PATH_MAP` 缺少路径时，开发环境打印中文警告，生产环境只静默过滤。
- 每批实施都必须同步更新 `TOOL_PATH_MAP`、`app.config.ts` 和本设计或实施计划中的入口清单。
- 每批验收都必须检查“后端返回但本地无路径”的工具不会显示。

第四批只做历史遗留清理；入口治理不是第四批才开始，而是每批的完成门槛。

## 7. 迁移批次

### 7.1 第一批：媒体与文档工具

迁移工具：

- 图片下载。
- 视频下载。
- 文档转 Markdown。
- Markdown 轻量编辑器。

完成标准：

- 小程序首页能显示这些工具并跳转。
- 每个页面都有加载、空状态、错误状态和成功状态。
- 上传、下载、复制行为在微信小程序环境可用。
- 不引入新后端能力，优先复用现有接口。
- `TOOL_PATH_MAP`、`app.config.ts` 和后端 `show_mobile` 一致。
- 后端返回但小程序无路径的工具不会显示。

### 7.2 第二批：学习内容

迁移工具：

- 课程学习。
- 技术内容。

完成标准：

- 课程列表、详情、章节阅读、测验提交流程可用。
- 技术内容列表、详情、标签或类型筛选可用。
- Markdown 阅读体验适配手机。
- 不迁移后台课程管理能力。
- `TOOL_PATH_MAP`、`app.config.ts` 和后端 `show_mobile` 一致。

### 7.3 第三批：统计

迁移工具：

- Token 统计只读面板。

完成标准：

- Token 工具只读，不触发本机扫描或危险清理。
- 支持按日、周、月和设备筛选已有数据。
- 不暴露刷新、同步、清空或设备重命名入口，除非另行确认并单独评审。
- `TOOL_PATH_MAP`、`app.config.ts` 和后端 `show_mobile` 一致。

AI 助手不作为第三批承诺内容。只有确认外部业务域名、web-view 合规性或内置聊天 API 后，才进入单独批次。

### 7.4 第四批：低优先级与历史遗留清理

治理内容：

- 清理历史遗留的错误 `show_mobile` 配置。
- 清理无效或过时的 `TOOL_PATH_MAP` 项。
- 对高风险工具保持默认隐藏。
- 如必须展示说明页，必须明确“暂不支持移动端”，不提供危险操作入口。

完成标准：

- 小程序工具列表没有死入口。
- 后端移动端显示配置与小程序实际能力一致。
- 暂不迁移工具有清晰说明，避免后续误开。

## 8. 关键工具功能设计

### 8.1 图片下载

流程：

1. 用户输入网页 URL。
2. 调用后端提取接口。
3. 展示图片列表，包括缩略图、格式、来源链接。
4. 用户可以预览图片、复制图片 URL、保存到相册。
5. 历史记录只读展示最近提取结果。

注意事项：

- 保存相册需要处理授权失败。
- 跨域、反爬、页面解析仍由后端处理。
- 第一版不做批量保存，避免权限和体验复杂度过高。

### 8.2 视频下载

流程：

1. 用户输入视频页 URL。
2. 调用提取或下载任务接口。
3. 展示任务状态：排队、处理中、完成、失败。
4. 完成后展示格式、大小、下载链接。
5. 小程序端优先复制下载链接或打开链接，不强制保存大文件。

注意事项：

- 大文件下载不适合小程序内直接保存。
- 轮询必须有超时和重试提示。
- 不做后台长任务通知，第一版保持前台轮询。

### 8.3 文档转 Markdown

流程：

1. 用户选择 Word、PDF、Excel 等文件。
2. 使用 `Taro.uploadFile` 上传到后端转换接口。
3. 返回 Markdown 内容后进入预览。
4. 支持复制 Markdown、查看历史、删除历史。
5. 文件过大时前端先提示限制。

注意事项：

- 微信文件选择能力要单独适配，不能照搬 Web `File`。
- 预览使用现有小程序 `Markdown` 组件，必要时做语法降级。
- 转换失败要展示后端错误原因。

### 8.4 Markdown 轻量编辑器

流程：

1. 默认打开本地草稿。
2. 编辑区和预览区使用 tabs 切换。
3. 支持复制全文、清空、保存草稿。
4. 可选增强：列出 OSS Markdown 文件、读取、保存。

不迁移内容：

- Web 端文件树。
- Monaco 编辑器。
- 高级搜索。
- 版本回滚。
- 桌面式多面板布局。

### 8.5 课程与技术内容

流程：

1. 展示课程或内容列表。
2. 详情页展示简介、章节或正文。
3. 学习页展示 Markdown 内容，底部提供上一章和下一章。
4. 测验页支持单选、多选、提交结果。

注意事项：

- 移动端阅读优先。
- 不迁移后台课程管理。
- 技术内容和课程共享 Markdown 阅读组件、标签组件和空状态组件。

### 8.6 Token 统计

流程：

1. 打开后加载健康状态和统计数据。
2. 顶部选择维度：日、周、月。
3. 支持设备筛选。
4. 展示摘要卡片、列表和简化趋势。

限制：

- 只读，不触发本机 Claude 或 OpenCode 扫描。
- 不提供清空数据入口。
- 第一版不提供刷新按钮，不暴露刷新、同步、清空或设备重命名入口。
- 第一版不提供设备重命名；设备列表仅用于筛选和展示。

### 8.7 AI 助手

AI 助手本轮不承诺迁移。Web 端当前是外部 iframe，需要先确认：

- 外部域名是否可加入微信小程序业务域名。
- 是否允许使用 `web-view` 呈现。
- 是否有可复用的内置聊天 API。
- 是否需要独立登录态和用户数据隔离。

若后续确认迁移，目标流程是：

1. 加载历史会话。
2. 发送消息。
3. 展示加载中和回复。
4. 支持重试和复制回复。
5. 与 `openclaw` 分开服务层，避免两个聊天工具互相污染。

## 9. 错误处理

所有新增小程序工具统一使用以下状态：

| 状态 | 表现 |
| --- | --- |
| 初始 | 展示输入区或选择文件按钮 |
| 加载中 | 按钮禁用，显示加载文案 |
| 空结果 | 显示空状态和下一步提示 |
| 失败 | 展示中文错误原因，保留用户输入 |
| 成功 | 展示结果、复制、预览、打开等操作 |

上传和下载类工具必须处理：

- 文件过大。
- 网络超时。
- 权限失败。
- 后端错误。
- 任务轮询超时。

用户可见错误统一使用中文 toast 或页面错误区。生产逻辑中不输出敏感信息，例如 token、完整鉴权下载 URL、数据库连接信息等。

## 10. 日志与安全

小程序端：

- 保留关键 `console.error`，用于开发排查。
- 用户可见错误用中文提示。
- 不输出敏感 token、鉴权参数、数据库连接信息。

后端：

- 本次迁移尽量不改后端。
- 如果接口日志不足，只在相关接口补充关键日志。
- 不做与迁移无关的重构。

安全治理：

- 高风险工具默认隐藏。
- 不在小程序暴露数据库、Redis、SSH、系统进程等危险操作。
- 下载链接优先复制或打开，避免在小程序内强行处理大文件。

下载、上传和外部内容类工具必须额外满足：

- 微信小程序合法域名已配置，接口域名、下载域名、上传域名分别确认。
- 下载 URL 带鉴权参数时不得完整写入日志。
- 下载 URL 必须有有效期或后端权限控制。
- 文档上传必须有文件类型白名单和大小上限。
- 图片和视频提取要对反爬、版权限制、空结果给出清晰中文提示。
- 历史记录必须按用户隔离，不能跨用户读取。
- 保存到相册或打开文件前必须处理授权拒绝。

## 11. 验证策略

小程序侧：

```bash
cd tools-mini-program
npm run build:weapp
npm run build:h5
```

如 TypeScript 检查可用，追加：

```bash
cd tools-mini-program
npx tsc --noEmit
```

后端侧若改动接口：

```bash
cd backend
python -m py_compile app/main.py
ruff check .
pytest
```

服务启停必须使用项目脚本：

```bash
python dev-services.py status
python dev-services.py restart
```

普通前端或后端代码变更优先依赖热重载，不主动重启服务。

### 11.1 批次手工验收清单

每个新增工具至少验证：

- 成功流程。
- 空结果。
- 后端 4xx/5xx 错误。
- 网络超时。
- 未登录或登录态失效。
- 权限拒绝，例如相册、录音、文件选择。
- 入口隐藏：后端返回但本地无路径时不展示。
- 入口跳转：`TOOL_PATH_MAP` 路径和 `app.config.ts` 注册一致。

下载、上传和转换类工具额外验证：

- 超出大小限制。
- 不支持文件类型。
- 任务轮询超时。
- 下载链接复制成功。
- 历史记录只显示当前用户数据。

## 12. 实施前置检查

每批实施前需要确认：

- 目标工具对应的后端接口是否已存在。
- 小程序是否需要新增分包页面路径。
- `TOOL_PATH_MAP` 是否与 `app.config.ts` 保持一致。
- 后端 `show_mobile` 是否符合实际移动端能力。
- 是否会引入新的依赖；如需引入依赖，必须单独确认。
- 是否有破坏性 API 变更；如有，必须单独设计迁移方案。

## 13. 非目标

- 不迁移 Web 管理后台。
- 不迁移桌面级数据库、Redis、SSH 和系统监控能力。
- 不重写后端工具服务。
- 不做所有工具一次性大爆炸式上线。
- 不把小程序 H5 作为第一优先平台。
