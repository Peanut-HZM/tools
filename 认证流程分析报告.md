# 数据库管理工具认证流程分析报告

## 问题现象

用户未登录时访问数据库管理工具页面，页面没有弹出登录框，而是显示了 "Authorization header missing" 的错误 toast（右上角红色提示）。

## 一、认证拦截器/守卫的完整代码

### 1.1 全局 401 处理器注册（App.tsx）

**文件**: `frontend/src/App.tsx`

```typescript
function GlobalAuthHandler() {
  const openLoginModal = useLoginModalStore((state) => state.openLoginModal);
  const { markUnauthorized } = useAuth();
  // 用 ref 保存最新函数引用，避免空依赖 useEffect 捕获过期闭包
  const markUnauthorizedRef = useRef(markUnauthorized);
  markUnauthorizedRef.current = markUnauthorized;
  const openLoginModalRef = useRef(openLoginModal);
  openLoginModalRef.current = openLoginModal;

  useEffect(() => {
    registerAuthFailureHandler(() => {
      // 401：清除失效 token 与用户态（仅已登录时递增 authVersion）
      markUnauthorizedRef.current();
      // 打开登录弹框（store 幂等：已打开时不重复触发）
      openLoginModalRef.current();
    });
  }, []);

  return <LoginModal />;
}
```

### 1.2 两套 HTTP 客户端与 401 拦截

#### 路径 A: authedFetch（api/http.ts）

```typescript
export type AuthFailureHandler = () => void;
let authFailureHandler: AuthFailureHandler | null = null;

export function registerAuthFailureHandler(handler: AuthFailureHandler): void {
  authFailureHandler = handler;
  // 挂载到全局，供 axios 拦截器访问
  (window as any).__authFailureHandler = handler;
}

export async function authedFetch(
  input: RequestInfo | URL,
  init?: RequestInit
): Promise<Response> {
  const response = await fetch(input, init);
  if (response.status === 401 && authFailureHandler) {
    authFailureHandler();  // ✅ 触发登录弹窗
  }
  return response;
}
```

**使用方**: `authApi.ts`（登录/注册/登出/获取用户信息/修改密码）

#### 路径 B: axios 实例（services/httpClientApi.ts）

```typescript
import axios from 'axios';
import { getAuthToken } from '../api/authApi';
import { registerAuthFailureHandler } from '../api/http';

// 全局 axios 401 拦截器
axios.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error?.response?.status === 401) {
      // 仅在客户端有 token 时触发（避免循环）
      if (getAuthToken()) {
        const handler = (window as any).__authFailureHandler;
        if (handler) handler();  // ✅ 触发登录弹窗
      }
    }
    return Promise.reject(error);
  }
);

const httpClient = axios.create({
  baseURL: `${API_BASE_URL}/http-client`,
  headers: { 'Content-Type': 'application/json' },
});

// 请求拦截器 - 添加 JWT token
httpClient.interceptors.request.use((config) => {
  const token = getAuthToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

**使用方**: HTTP API Client 工具专用

#### 路径 C: 原生 fetch（api/databaseToolApi.ts）❌ **问题所在**

```typescript
const BASE_URL = `${API_BASE_URL}/database-tool`;

async function fetchWithTimeout(url: string, options: RequestInit & { timeout?: number } = {}) {
  const { timeout = 15000, ...rest } = options;
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);
  try {
    const response = await fetch(url, {  // ❌ 使用原生 fetch，非 authedFetch
      ...rest,
      signal: controller.signal,
    });
    return response;
  } catch (err: any) {
    if (err.name === 'AbortError') {
      throw new Error(`请求超时（${timeout / 1000} 秒）`);
    }
    throw err;
  } finally {
    clearTimeout(timer);
  }
}

async function handleResponse<T>(response: Response): Promise<T> {
  if (!response.ok) {
    const error = await response.json().catch(() => ({ detail: response.statusText }));
    // ❌ 401 时不触发登录弹窗，直接抛错
    const err = new Error(typeof error.detail === 'string' ? error.detail : JSON.stringify(error.detail));
    (err as any).detail = error.detail;
    (err as any).response = { detail: error.detail };
    throw err;
  }
  return response.json();
}

// 所有数据库 API 都使用 fetchWithTimeout + getAuthHeaders()
export async function getDatabases(includePassword = false): Promise<DatabaseConfig[]> {
  const query = includePassword ? '?include_password=true' : '';
  const response = await fetchWithTimeout(`${BASE_URL}/databases${query}`, {
    headers: getAuthHeaders(),  // ❌ token 为空时不带 Authorization header
    timeout: 30000
  });
  const data = await handleResponse<DatabaseConfig[]>(response);
  return data;
}
```

**使用方**: 数据库管理工具（DatabaseTool）

## 三、API 请求发送时如何携带 token

### 3.1 Token 存储（localStorage）

**文件**: `frontend/src/api/authApi.ts`

```typescript
export function getAuthToken(): string | null {
  return localStorage.getItem('auth_token');
}

export function setAuthToken(token: string): void {
  localStorage.setItem('auth_token', token);
}

export function removeAuthToken(): void {
  localStorage.removeItem('auth_token');
}
```

### 3.2 附加 Authorization header

```typescript
export function getAuthHeaders(): HeadersInit {
  const token = getAuthToken();
  if (token) {
    return {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`
    };
  }
  // ❌ token 为空时，静默返回不带 Authorization 的头
  return {
    'Content-Type': 'application/json'
  };
}
```

**问题**: 当 token 为空时，`getAuthHeaders()` **静默返回不带 Authorization 的头**，不会在前端抛错或拦截。此时后端会返回 401 "Authorization header missing"。

## 四、401 响应的处理链路

### 4.1 后端返回 401 的逻辑

**文件**: `backend/app/middleware/auth_middleware.py`

```python
async def get_current_user_id(authorization: Optional[str] = Header(None)) -> str:
    if not authorization:
        raise HTTPException(
            status_code=401, 
            detail="Authorization header missing",  # ❌ 英文错误消息
            headers={"WWW-Authenticate": "Bearer"}
        )
    
    if not authorization.startswith("Bearer "):
        raise HTTPException(
            status_code=401, 
            detail="Invalid authorization header format. Expected 'Bearer <token>'",
            headers={"WWW-Authenticate": "Bearer"}
        )
    
    token = authorization[7:]
    
    if not token:
        raise HTTPException(
            status_code=401, 
            detail="Token is empty",
            headers={"WWW-Authenticate": "Bearer"}
        )
    
    try:
        auth_service = get_auth_service()
        token_data = auth_service.verify_token_data(token)
        return token_data.user_id
    except ValueError as e:
        raise HTTPException(
            status_code=401, 
            detail=str(e),
            headers={"WWW-Authenticate": "Bearer"}
        )
```

**响应格式**:
```json
{
  "detail": "Authorization header missing"
}
```

### 4.2 前端处理链路对比

#### ✅ 正常路径（authedFetch）

```
后端返回 401
  ↓
authedFetch 检测 response.status === 401
  ↓
调用 authFailureHandler()
  ↓
GlobalAuthHandler 注册的回调：
  1. markUnauthorized() → 清除 token + 用户态
  2. openLoginModal() → 弹出登录框
  ↓
用户看到登录弹窗 ✅
```

#### ❌ 问题路径（databaseToolApi.ts 的原生 fetch）

```
后端返回 401 {"detail": "Authorization header missing"}
  ↓
fetchWithTimeout 返回 Response
  ↓
handleResponse 检测 !response.ok
  ↓
读取 response.json().detail → "Authorization header missing"
  ↓
throw new Error("Authorization header missing")  ❌ 不触发登录弹窗
  ↓
调用方（SQLExecutor）catch (error)
  ↓
toast.error(error.message) → 显示 "Authorization header missing"  ❌ 英文错误 toast
  ↓
用户看到英文错误 toast，没有登录弹窗 ❌
```

## 五、根因分析

### 5.1 核心问题

**数据库管理工具的 API 调用使用原生 `fetch`，而非 `authedFetch`，导致 401 响应不触发全局登录弹窗。**

### 5.2 问题链路

1. **工具配置**: `database-tool` 的 `require_login=False`（未设置需要登录）
   - 用户可以在首页直接点击进入，不触发登录拦截
   - 用户可以直接访问 `/tools/database-tool` 或 `/workspace` 路由

2. **路由无守卫**: `/tools/database-tool` 路由没有认证守卫
   - 对比其他工具：`TokenUsage`、`K8sTool`、`ImageGeneration`、`HttpApiClient` 都渲染了 `<RequireAuthNotice />`
   - `DatabaseTool` 直接渲染，未检查 `isAuthenticated`

3. **子组件无认证检查**: `SQLExecutor`、`TableDataViewer` 等子组件在用户操作时直接调用 API
   - 例：用户点击"执行 SQL"按钮 → `api.executeSQL()` → 未检查 `isAuthenticated`
   - `getAuthHeaders()` 在无 token 时静默返回不带 Authorization 的头

4. **后端返回 401**: 后端检测到缺少 Authorization header，返回 `{"detail": "Authorization header missing"}`

5. **前端错误处理缺陷**:
   - `databaseToolApi.ts` 的 `handleResponse` 只抛出 Error，**不触发登录弹窗**
   - `SQLExecutor` 捕获错误后调用 `toast.error(error.message)`，直接显示英文原始消息
   - **全局 401 处理器未被调用**，因为使用的是原生 `fetch` 而非 `authedFetch`

### 5.3 对比其他工具

| 工具 | require_login | 使用 RequireAuthNotice | HTTP 客户端 | 401 弹窗 |
|------|--------------|------------------------|------------|---------|
| TokenUsage | ✅ | ✅ | authedFetch | ✅ |
| K8sTool | ✅ | ✅ | authedFetch | ✅ |
| ImageGeneration | ✅ | ✅ | authedFetch | ✅ |
| HttpApiClient | ✅ | ✅ | axios 拦截器 | ✅ |
| MarkdownEditor | ✅ | ❌（使用 AuthGuard） | authedFetch | ✅ |
| **DatabaseTool** | **❌** | **❌** | **原生 fetch** | **❌** |
| RedisTool | ❓ | ❓ | ❓ | ❓ |
| SSHTool | ❓ | ❓ | ❓ | ❓ |

## 六、修复建议

### 方案 A: 统一使用 authedFetch（推荐）

修改 `api/databaseToolApi.ts`，将 `fetchWithTimeout` 改为使用 `authedFetch` 或复用其 401 处理逻辑：

```typescript
import { authedFetch } from './http';

async function fetchWithTimeout(url: string, options: RequestInit & { timeout?: number } = {}) {
  const { timeout = 15000, ...rest } = options;
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);
  try {
    const response = await authedFetch(url, {  // ✅ 改用 authedFetch
      ...rest,
      signal: controller.signal,
    });
    return response;
  } catch (err: any) {
    if (err.name === 'AbortError') {
      throw new Error(`请求超时（${timeout / 1000} 秒）`);
    }
    throw err;
  } finally {
    clearTimeout(timer);
  }
}
```

### 方案 B: 添加 RequireAuthNotice 守卫

在 `DatabaseTool` 顶层添加认证检查，未登录时显示 `<RequireAuthNotice />`：

```typescript
import RequireAuthNotice from '../Common/RequireAuthNotice';
import { useAuth } from '../../stores/authStore';

const DatabaseToolContent: React.FC = () => {
  const { isAuthenticated } = useAuth();
  
  if (!isAuthenticated) {
    return <RequireAuthNotice />;  // ✅ 未登录时显示登录提示
  }
  
  // ... 原有逻辑
};
```

### 方案 C: 本地化错误消息

在 `handleResponse` 或调用方将英文错误转换为中文：

```typescript
async function handleResponse<T>(response: Response): Promise<T> {
  if (!response.ok) {
    const error = await response.json().catch(() => ({ detail: response.statusText }));
    const detail = typeof error.detail === 'string' ? error.detail : JSON.stringify(error.detail);
    
    // ✅ 本地化映射
    const localizedMessage = localizeErrorMessage(detail);
    const err = new Error(localizedMessage);
    (err as any).detail = error.detail;
    throw err;
  }
  return response.json();
}

function localizeErrorMessage(detail: string): string {
  if (detail.includes('Authorization header missing')) {
    return '请先登录后再使用此功能';
  }
  if (detail.includes('Invalid token')) {
    return '登录已过期，请重新登录';
  }
  // ... 其他映射
  return detail;
}
```

### 推荐组合方案

**方案 A + 方案 B + 方案 C**：
1. 统一使用 `authedFetch`，确保 401 触发登录弹窗
2. 添加 `<RequireAuthNotice />` 守卫，阻止未登录用户进入页面
3. 本地化错误消息，避免显示英文原始文本
