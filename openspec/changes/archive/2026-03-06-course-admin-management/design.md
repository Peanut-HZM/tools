## Context

**背景：**
- OpenSpec VibeCoding 互动课程功能已经实现了基本的学习页面和后台 API
- 现有的后端 API 已经支持章节、测验、资源的 CRUD 操作，但缺乏前端管理界面
- 数据库模型已经完善，包括章节表、测验表、题目表、选项表、资源表和用户进度表
- 管理员需要直接调用 API 或操作数据库来管理课程内容，效率低下

**当前系统架构：**
- 后端：FastAPI + SQLAlchemy + SQLite/PostgreSQL
- 前端：React 18 + TypeScript + Vite + TailwindCSS
- 后台管理系统已经存在，包含工具管理、用户管理、对话管理、Agent 管理、OSS 管理、LLM 配置等模块

**约束：**
- 保持与现有 API 的兼容性
- 复用现有的后台管理布局组件和样式
- 数据模型不需要大的改动，已有字段已足够

## Goals / Non-Goals

**Goals:**
- 在后台管理系统中新增课程管理模块，支持章节、测验、资源的可视化管理
- 实现章节的增删查改、排序调整、锁定/解锁控制
- 实现测验的增删查改，支持题目和选项的嵌套管理
- 实现资源的增删查改，支持多种资源类型（代码示例、对比材料、视频、模板）
- 前端课程学习页面与后台管理数据完全对接
- 提供富文本/Markdown 编辑器用于章节内容编辑

**Non-Goals:**
- 不改变现有的课程学习流程和体验
- 不修改数据库表结构（现有模型已满足需求）
- 不涉及用户认证/授权系统的改动
- 不包含视频上传功能（仅支持外链）

## Decisions

### 1. 后台管理页面结构

**决策：** 在现有 AdminLayout 下新增 CourseManagement 页面，采用左侧导航 + 右侧内容的布局

**理由：**
- 复用现有的后台管理框架和样式
- 与工具管理、用户管理等页面保持一致的用户体验
- 左侧导航可以快速切换章节、测验、资源管理

**替代方案考虑：**
- 方案 A：为每个实体（章节、测验、资源）创建独立页面
  - 缺点：页面太多，导航复杂
- 方案 B：使用模态框进行编辑
  - 缺点：编辑复杂内容时空间不足，体验差

### 2. 章节内容编辑器

**决策：** 使用 Monaco Editor 作为 Markdown 编辑器，支持实时预览

**理由：**
- 项目已有 Monaco Editor 依赖（@monaco-editor/react）
- 提供良好的代码高亮和编辑体验
- 支持分栏显示编辑和预览

### 3. 测验题目管理交互

**决策：** 在测验管理页面中，使用可展开的题目列表，每个题目内嵌选项管理

**理由：**
- 题目和选项是一对多关系，嵌套展示符合数据结构
- 可拖拽排序，直观调整题目顺序
- 减少页面跳转，提升编辑效率

### 4. 状态管理

**决策：** 使用 Zustand 创建课程管理 store，统一管理章节、测验、资源的数据状态

**理由：**
- 项目已有 Zustand 使用经验
- 避免过多的 Props 传递
- 支持跨组件共享状态

### 5. API 调用封装

**决策：** 创建 openspecCourseAdmin.ts 服务文件，封装所有后台管理相关的 API 调用

**理由：**
- 与前端学习页面的 API 服务分离，职责清晰
- 统一管理错误处理和类型定义
- 便于后续维护和扩展

## Risks / Trade-offs

### 风险 1：Markdown 编辑器预览样式不一致

**风险描述：** Monaco Editor 编辑的 Markdown 内容在预览时可能与最终展示效果不一致

**缓解措施：**
- 使用与前端展示相同的 react-markdown 配置
- 添加实时预览功能，编辑时同步显示效果

### 风险 2：测验题目和选项的嵌套数据结构复杂

**风险描述：** 测验包含题目，题目包含选项，嵌套增删改逻辑复杂，容易出现状态不同步

**缓解措施：**
- 使用不可变数据更新模式
- 提交前进行数据校验
- 添加完善的错误提示

### 风险 3：章节排序冲突

**风险描述：** 多个管理员同时调整章节顺序可能导致数据冲突

**缓解措施：**
- 前端乐观更新，后端最终一致性
- 添加版本控制或时间戳校验（后续优化）

### 风险 4：大文件内容存储

**风险描述：** 章节内容如果包含大量代码或 Markdown，可能导致数据库存储和网络传输压力

**缓解措施：**
- 限制章节内容大小（前端校验）
- 使用分页加载章节列表
- 后续可考虑对象存储

## Migration Plan

### 部署步骤：
1. 后端 API 已经存在，无需额外部署
2. 部署前端后台课程管理页面
3. 更新前端学习页面的 API 对接逻辑（如需要）

### 回滚策略：
- 前端页面回滚：撤销相关组件和路由即可
- 不影响现有数据库数据
- 如有数据变更，提供 SQL 回滚脚本
