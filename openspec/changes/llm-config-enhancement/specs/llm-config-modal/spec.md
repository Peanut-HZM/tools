## ADDED Requirements

### Requirement: 用户可以通过弹窗添加新的大模型配置
系统 SHALL 提供弹窗式界面，允许用户填写配置名称、供应商、Base URL、API Key、模型名称等信息来创建新的大模型配置。

#### Scenario: 打开新增弹窗
- **WHEN** 用户点击"添加配置"按钮
- **THEN** 系统显示新增配置弹窗，表单字段为空

#### Scenario: 提交新配置
- **WHEN** 用户填写所有必填字段并点击"创建配置"按钮
- **THEN** 系统验证表单，调用后端 API 创建配置，成功后关闭弹窗并刷新列表

#### Scenario: 取消新增
- **WHEN** 用户点击"取消"按钮或弹窗外部区域
- **THEN** 弹窗关闭，表单数据不清空（保留以便下次编辑）

### Requirement: 用户可以通过弹窗编辑已有配置
系统 SHALL 提供弹窗式界面，允许用户编辑已有的大模型配置。API Key 字段留空表示不修改原 Key。

#### Scenario: 打开编辑弹窗
- **WHEN** 用户点击配置行的"编辑"按钮
- **THEN** 系统显示编辑弹窗，表单预填当前配置信息（API Key 字段为空）

#### Scenario: 保存编辑
- **WHEN** 用户修改字段并点击"保存修改"按钮
- **THEN** 系统调用后端 API 更新配置，成功后关闭弹窗并刷新列表

### Requirement: 用户可以通过弹窗确认删除配置
系统 SHALL 提供确认弹窗，防止误删配置。

#### Scenario: 打开删除确认弹窗
- **WHEN** 用户点击配置行的"删除"按钮
- **THEN** 系统显示删除确认弹窗，显示配置名称

#### Scenario: 确认删除
- **WHEN** 用户点击确认删除按钮
- **THEN** 系统调用后端 API 删除配置，成功后刷新列表

#### Scenario: 取消删除
- **WHEN** 用户点击"取消"按钮
- **THEN** 弹窗关闭，无任何操作

### Requirement: 弹窗应支持表单验证
系统 SHALL 在用户提交前验证表单数据的合法性。

#### Scenario: 空名称提交
- **WHEN** 用户不填写配置名称就提交
- **THEN** 系统显示红色错误提示，阻止提交

#### Scenario: 无效 URL 格式
- **WHEN** 用户填写无效的 Base URL 格式
- **THEN** 系统显示 URL 格式错误提示
